# StartupAI v14: Technical Overview & Documentation

StartupAI is a high-performance "AI Operating System" designed for founders. It centralizes the chaotic process of starting a company into a structured, data-driven workflow encompassing strategy, execution, and fundraising.

---

## 1. Core Mission
Help founders navigate the journey from **Idea → Clarity → Execution → Fundraising** using architectural structure and AI-driven strategic inference.

---

## 2. Technical Stack

| Layer | Technology | Implementation |
| :--- | :--- | :--- |
| **Frontend** | React 19 | Pure composition root with stable state management. |
| **Routing** | React Router 7 | `createHashRouter` for stable navigation in static/Vite environments. |
| **Styling** | Tailwind CSS | Editorial Stone Palette with architectural whitespace. |
| **AI Engine** | Gemini 3 API | Modular services using Pro (Thinking) and Flash (Execution) models. |
| **Intelligence** | Google Search | Real-time market grounding for investor and competitor research. |
| **Inference** | Thinking Mode | 4k-8k token budgets for deep reasoning on startup readiness and risk. |

## 3. Directory Architecture

The system follows a modular React structure where business logic (Inference) is decoupled from presentation (Pages).

```text
/ (Project Root)
├── services/
│   └── ai/                   # Modular Inference Engines (CRM, Dashboard, Wizard, etc.)
├── components/
│   ├── wizard/               # Setup steps for the 6-stage initialization
│   └── ThreePanelLayout.tsx  # Core Architectural UI Shell
├── pages/
│   ├── Dashboard.tsx         # Daily Command Center
│   ├── Wizard.tsx            # Initial Data Ingestion
│   ├── CRM.tsx               # Relationship Pipeline
│   ├── Discovery.tsx         # AI Prospecting Scout
│   ├── Projects.tsx          # Execution Health Monitoring
│   ├── Tasks.tsx              # Granular Execution Backlog
│   └── Documents.tsx          # Strategic Artifacts & Memos
├── docs/                     # PRD, Roadmap, and Implementation Plans
├── router.tsx                # Centralized Navigation Logic
└── types.ts                  # Shared Domain Model Definitions
```

## 4. Design Language: "The Stone Aesthetic"

StartupAI adheres to a strict "Editorial Architectural" design system:
- **Palette**: Monochromatic Stone palette (`stone-50` to `stone-900`).
- **Typography**: 
    - `Merriweather` (Serif): Used for strategy, narrative, and AI insights.
    - `Inter` (Sans): Used for operational data, metrics, and UI controls.
- **Color Logic**: Color is reserved exclusively for status (Emerald = Healthy, Amber = Warning, Rose = Critical).
- **Structure**: The **Three-Panel Layout** ensures that context (Left), execution (Main), and intelligence (Right) are always visible.

---

## 5. AI Integration Framework

### The Strategic Inference Engine
Every insight generated by the AI follows the **3-Question Framework** in the persistent Intelligence panel:
1. **What does this mean?** (Data interpretation)
2. **What should I do next?** (Actionable tactical advice)
3. **Why does this matter now?** (Strategic urgency)

### Specialized Agents
- **Scout Agent**: Uses Search Grounding to find investors and customers.
- **Analyst Agent**: Evaluates project health and startup readiness scores.
- **Narrative Agent**: Refines founder drafts into investor-ready "Narratives."
- **Capital Agent**: Develops fundraising strategies based on burn rate and goals.

---

## 6. Primary Workflows

### Initialization (The Wizard)
A 6-step guided setup that extracts data from the startup's URL, analyzes the business model, identifies competitive moats, and generates the first sprint of tasks.

### Command (The Dashboard)
The daily "Next Best Action" (NBA) logic weighs the entire startup profile against the active task backlog to provide the single most important priority for the day.

### Relationships (The CRM)
A Kanban-style pipeline for managing investors and customers, enriched by AI research that identifies portfolio conflicts and warm intro points.

---

## 7. Data Sovereignty
While AI provides suggestions, it never replaces founder judgment. The "Mark Complete" and "Apply Refinement" patterns ensure the founder remains the final decision-maker in the Operating System.
